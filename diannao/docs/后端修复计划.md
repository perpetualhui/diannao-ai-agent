## 步骤 1：关闭公开的演示 token

**问题**：`POST /v1/demo/token` 任何人可调用，直接拿到 `diannaoxy`（管理员）token。

**改法**（`services/api/src/server.ts:316`）
- 默认关闭：只有显式设置 `DEMO_MODE=1` 才允许。
- 当前逻辑是 `DEMO_MODE === '0'` 才禁用，反了，改为 `DEMO_MODE !== '1'` 禁用。
- 部署时在 `.env` 显式设 `DEMO_MODE=1` 供演示页使用；生产不设即为关闭。

**验证**
- 不设 `DEMO_MODE`：`POST /v1/demo/token` → 403。
- 设 `DEMO_MODE=1`：→ 200。
- 演示页 `/wechat-demo.html` 仍可用（部署时带 1）。

**回滚**：改回判断条件。

## 步骤 2：网关自动绑定改为「每人独立空白空间」

**问题**：新微信首次发消息自动绑定 `staff-a`，能看演示店真实客户数据。

**改法**
1. 新增内部接口 `POST /v1/gateway/provision`（带内部密钥 `GATEWAY_PROVISION_KEY`）：
   - 入参：`sender_id`
   - 行为：为该 sender 创建独立租户 + staff 账号（随机登录名/密码），返回凭证
   - 幂等：同一 sender 重复调用返回同一账号
2. 网关 `handleWebhook` 的自动绑定分支改为：
   - 先调 `provision` 拿独立账号
   - 失败时回退为「未绑定」提示（不授予任何数据权限）
3. 删除 `DIANNAO_AUTO_LOGIN=staff-a` 的默认值。

**验证**
- 新 sender 发「查一下尾号1234」→ 返回「暂无记录」（独立空白空间），不是张女士。
- 同 sender 发「新建客户：王姐，尾号6688」→ 建档成功。
- 演示店账号 `staff-a` 数据不受影响。

**取舍**：演示体验从「新微信直接看到张女士」变成「独立空白空间」。这是安全与演示的取舍，按用户确认执行。

**回滚**：恢复 `DIANNAO_AUTO_LOGIN` 分支。

## 步骤 3：删除员工时撤销会话

**问题**：`removeAccount` 只删账号表，membership 和内存 session 仍在，旧 token 8 小时内有效。

**改法**（`services/api/src/auth.ts:72`）
- `removeAccount` 内调用 `revokeMembership`（或直接把 membership 标记 revoked 并 version+1）。
- 清理 `SESSIONS` 中该 user 的全部 token。
- 保留审计记录。

**验证**
- 管理员新增员工 → 员工登录拿 token → 管理员删除该员工 → 员工用旧 token 调接口 → 401。
- 员工重新登录 → 401（账号已删）。

**回滚**：去掉撤权调用。

## 步骤 4：存储明细按租户过滤

**问题**：`/v1/admin/storage/detail` 返回全局数据，管理员可见其他租户（含个人用户）资料。

**改法**（`services/api/src/server.ts:1152`）
- 所有表行按 `principal.tenant_id` 过滤。
- 账号/绑定列表仅保留本租户相关项（通过 membership 关联）。
- 存储概览仍显示全局快照大小（不含内容）。

**验证**
- `diannao` 管理员看存储明细 → 只有租户 A 的 6 个客户。
- 新建个人租户用户建 1 个客户 → 管理员明细看不到该客户。

**回滚**：恢复全局切片。

## 步骤 5：密码加盐哈希

**问题**：accounts 表明文存密码。

**改法**
- `db.ts` / `auth.ts`：使用 Node 内置 `crypto.scryptSync`，存储格式 `scrypt$salt$hash`。
- 兼容旧数据：登录时若密码无 `scrypt$` 前缀，按明文比对成功一次后自动升级为哈希。
- 新增/注册/改密统一走哈希。

**验证**
- 现有账号仍能登录（自动升级）。
- 直接查 `accounts` 表看不到明文。
- 新注册账号写入即为哈希。

**回滚**：保留明文兼容分支（不删旧格式支持）。

## 步骤 6：限流

**问题**：登录、注册、绑定码校验无频率限制。

**改法**
- 进程内滑动窗口限流（内存 Map，按 IP + 路径）：
  - `/v1/auth/login`：每 IP 每分钟 10 次
  - `/v1/auth/register`：每 IP 每小时 5 次
  - `/v1/setup/verify`：每 IP 每分钟 10 次
- 超限返回 429 + `Retry-After`。

**验证**
- 连续 11 次错误登录 → 第 11 次 429。
- 等 60 秒后恢复。

**回滚**：限流阈值调到极大或删除中间件。

## 步骤 8：后台改绑定把网关口令抹掉 → 微信端「AI 不可用」（P0，2026-11-08）

**现象**：微信里问「查一下尾号1234」，ClawBot 回「店脑服务暂不可用（店脑 API 登录失败 401）」。

**根因**：`removeBinding` / `/v1/admin/bindings/update` 用 `readBindings()`（对外安全视图，已剥离 password）读文件再整体写回，
`users.json` 里的 `password` 被抹掉；网关 `ensureToken` 拿不到密码 → 登录 401 → 工具报错。

**改法**
- `services/api/src/server.ts`：两处改用 `readBindingsRaw()`，写回时保留 password；换归属时给新账号重置一次网关密码。
- `services/api/src/auth.ts`：新增 `resetPassword(loginName, password)`（保留账号与数据，清掉该用户会话）。
- `/v1/gateway/provision`：同一 sender 已绑定时不再新开租户，只重置网关密码（`reset:true` 显式触发）。
- `adapters/wechat/gateway.mjs`：`ensureToken` 加凭据自愈——密码缺失或登录 401 时调 provision(reset) 写回 users.json 再重试。

**验证**
- 网关探针：`查一下尾号1234上次买什么` → 返回张女士真实购买记录。
- OpenClaw agent 实测：`toolSummary.calls=1, failures=0`，回包为真实数据。
- 回归：25 项全通过（新增「网关凭据可用」一项）。
